# Project Commands

The CMake source directory is `CyberRayne/`.

## Linux Debug

```bash
cmake -S CyberRayne --preset linux-debug
cmake --build CyberRayne/out/build/linux-debug
ctest --test-dir CyberRayne/out/build/linux-debug --output-on-failure
```

## Linux Release

```bash
cmake -S CyberRayne --preset linux-release
cmake --build CyberRayne/out/build/linux-release
ctest --test-dir CyberRayne/out/build/linux-release --output-on-failure
```

# Cyber Rayne Implementation Plan

This document tracks the approved implementation roadmap for the Cyber Rayne vertical slice. Pick up work from the **Current Phase** below and continue in phase order.

## Vision

Cyber Rayne is a turn-based JRPG (Final Fantasy 9 reimagined in a cyberpunk setting). It uses a custom C++20/Vulkan engine. The immediate goal is a complete vertical slice: a full gameplay loop from menu through exploration to ATB combat.

## Completed Work

### Phase 0: Stabilize the Prototype — COMPLETE

- Registered gameplay tests with CTest.
- Decoupled core gameplay tests from Vulkan / platform dependencies.
- Added always-on checks for both Debug and Release builds.
- Added CMake presets for Linux Debug/Release and Windows x64.
- Added CI gameplay test execution.
- Introduced explicit `InputAction` events and edge-triggered keyboard handling.
- Replaced owning raw pointers with smart pointers (`std::unique_ptr`, `std::shared_ptr`).
- Decoupled battle logic from `UIManager`.
- Fixed derived enemy stats not being initialized.
- Fixed enemy respawns accumulating duplicate enemies.
- Fixed incorrect enemy maximum-health display.
- Removed recurring per-frame diagnostic output.
- Documented project commands (this file).

### Phase 1: Renderer and UI Foundation — COMPLETE

- Added an embedded 8x8 monospace bitmap font atlas generated by `tools/generate_bitmap_font.py`.
- Added `BitmapFont`, `TextRenderer`, and renderer UV-region support for atlas-based text rendering.
- Extended sprite push constants and shaders with per-sprite color and UV region.
- Added `loadTextureFromMemory` and `renderColoredRectPixels` to `VulkanRenderer`.
- Built reusable UI primitives: `UIWidget`, `UILabel`, `UIButton`, `UIPanel`, `UIProgressBar`, and `UIRoot`.
- Replaced hard-coded image-button battle/menu UI with data-driven `UIButton` widgets and text labels.
- Replaced placeholder battle stats with working HP progress bars and text labels for player and enemies.
- Added a Vulkan-free `BitmapFontTest` to verify atlas generation and glyph UV mapping.

## Current Phase

### Phase 2: Party Model and ATB Combat — COMPLETE

- Introduced a `Combatant` base interface shared by `Player` and `Enemy`.
- Added `Party` class with Rayne + fixed companions (Cyph the Mage, Vash the Rogue).
- Implemented ATB gauges: speed-based fill, ready queue, and per-character turns.
- Rewrote `BattleSystem` to operate on a unified `Combatant` list with party + enemies.
- Expanded battle actions: attack (with living target selection), magic (ally/enemy auto-target), item use, defend (guarding stance), and flee.
- Added a `StatusEffect` framework with poison/regen tick effects.
- Updated `UIManager` to show per-party-member HP/ATB bars and the current actor's name.
- Updated `BattleSystemTest` to verify ATB fill, player turns, defeat detection, and status effects.

## Current Phase

## Working Rules

1. Follow phase order; do not skip ahead.
2. Keep the custom C++20/Vulkan engine.
3. Maintain a fixed protagonist (Rayne).
4. Prefer always-on checks over `assert` in test code.
5. Keep gameplay logic independent from rendering.
6. Run the relevant build preset and CTest after every meaningful change.
7. Update this plan when a phase is completed.
