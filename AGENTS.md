# Cyber Rayne Implementation Plan

This document tracks the approved implementation roadmap for the Cyber Rayne vertical slice. Pick up work from the **Current Phase** below and continue in phase order.

## Vision

Cyber Rayne is a turn-based JRPG (Final Fantasy 9 reimagined in a cyberpunk setting). It uses a custom C++20/Vulkan engine. The immediate goal is a complete vertical slice: a full gameplay loop from menu through exploration to ATB combat.

### Phase 6: Cyberpunk Classes, Abilities, and Reachable Combat — COMPLETE

**Class rename.** `CharacterClass` is now `NETRUNNER` / `SOLO` / `INFILTRATOR`, replacing
Mage / Warrior / Rogue. Enumerator order is unchanged, because `SaveSystem` persists the
class as a bare ordinal — **renaming is safe, reordering silently corrupts saves.** Added
`Player::classToString` / `classFromString` / `isValidClassOrdinal` and routed the display
name and asset filenames through them, replacing three ad-hoc conversion sites. Character
portraits are now derived per option from `charClass` rather than a positional list. The
`Netrunner` *enemy* was renamed `BlackICE` to free the name for the player class. Class art
lives in `assets/characters/<lowercase class>.png`.

**Combat is reachable.** Two bugs made it unreachable, neither of which was missing content:
- `World::render` drew enemies and NPCs at raw tile coordinates treated as NDC, skipping the
  viewport transform. Every entity in the game rendered off-screen. The viewport math now
  lives in `Map::getViewport` / `Map::worldToNdc`, shared by tile, entity, and player
  rendering, so the three paths cannot drift apart again.
- Enemies spawned at four hardcoded corners with no walkability check — two inside buildings
  on Neo-Kyoto Central, three outside the bounds of the smaller Corporate Plaza. Replaced with
  a walkable-tile search that avoids occupied tiles and keeps its distance from the player.

Both encounter styles are live: walking into a visible enemy, and a per-zone step-based
random roll (`EncounterTable::getEncounterRate`). Both move their enemies into
`World::m_activeEncounter`, which owns them for the fight — taking them off the map is what
stops a won battle from retriggering on the same tile. Battles are scoped to the triggering
group rather than every enemy on the map.

**Status effects and equipment now do something.** `StatusEffect::update()` was never called,
so effects never expired; `onTick` applied full magnitude every frame (~1200 dmg/sec for a
magnitude-20 poison at 60fps). Added a tick accumulator and wired expiry. `DEFENSE_UP/DOWN`,
`ATTACK_UP/DOWN`, `SLOW`, and `STUN` now change real numbers through
`Combatant::getEffectiveStrength/getEffectiveDefense/getAtbSpeedMultiplier/isStunned`.
Equipment bonuses reach those same accessors via virtual `Item::getAttackBonus/getDefenseBonus`,
so no downcast is needed. Player and enemy mitigation share one formula with a damage floor —
previously enemies subtracted full defense and a level-1 character did literally zero damage
to a StoneGolem.

**Ability system.** `Ability` + `AbilityRegistry` replace `Spell`, which was never instantiated
anywhere and hard-gated to Mage. Abilities operate on `Combatant`, so party and enemies share
one execution path and the four `static_cast<Player*>` sites in `BattleSystem` are gone. Cost
is validated *before* the turn is committed — an unaffordable ability is rejected instead of
silently burning the turn. `submitPlayerAction` takes an `ActionRequest` (ability, item, and
target indices) instead of one overloaded int, which is what makes manual targeting and
ally-targeted healing possible. Four abilities per class, unlocked by level; enemy kits keyed
by type name.

**Battle UI** is data-driven off the acting character's ability list, with working
`ABILITY_SELECTION` and `TARGET_SELECTION` states (previously declared but dead), generic grid
navigation instead of hardcoded 2×2 arithmetic, a reachable Flee entry, and CANCEL to back out.
`UIManager::BattleAction` is now an alias of `BattleSystem::BattleAction`, removing the
hand-written translation switch in `GameState`.

**Also fixed along the way:** the save loader called `setLevel()` before its `levelUp()` replay
loop, so the loop never ran and a high-level character loaded with level-1 stats; ATB pushed a
full-gauge combatant onto the ready queue every frame; `m_rewardedEnemies` was never cleared
between battles; per-frame renderer diagnostics spammed ~30k lines per run.

**Dev shortcut:** `CYBERRAYNE_START=world ./CyberRayne` skips the menus into exploration.

13 CTest suites pass, including new `AbilityTest`, `StatusEffectTest`, and `EncounterTest`.

## Roadmap to Vertical Slice Lock (planned 2026-11-10)

An audit on 2026-11-10 found that phases 0-6 built and tested the systems, but several
are not connected to the running game: NPCs cannot be talked to (no interact input, no
`DialogueSystem` in `GameState`), nothing starts or advances a quest, `saveGame()` is
never called, audio is a stub, and the pause / game-over / victory screens are blank.
Phases 7-13 close those gaps.

**Scope decisions (user, 2026-11-10):**
- The slice is the existing three-quest chain only ("The Data Chip" → "Corporate
  Intrusion" → "The Truth"). Further story and world progression is deferred.
- Saving is allowed at any time from the pause menu (no save points).
- Art is generated externally, then conformed with `tools/spriteprep.py` and gated by
  `tools/validate_assets.py`. `spriteprep.py` does not create art; it only conforms it.
- Every character sprite on disk is a placeholder. All characters get new sprites,
  including Cyph and Vash, who get their own files rather than sharing class sprites.

### Phase 8: Story Loop — COMPLETE (2026-11-10)

The three-quest chain is playable start to finish.

- **`StoryDirector`** (`systems/StoryDirector.{h,cpp}`) is the single owner of story logic:
  what each NPC says at each point, which events start quests and complete objectives,
  which fixed fights exist, and which maps are locked. It keeps no state of its own beyond
  a notification queue — everything is derived from the `QuestLog`, so saving the quest log
  saves the story. `ContentFactory::attachNPCDialogues` now delegates to it.
- **Talking** uses CONFIRM (Enter) next to an NPC rather than a separate interact action.
  `GameState` owns a `DialogueSystem` and reports each node to the director; nodes with IDs
  `NODE_*` carry story effects, and each effect re-checks its precondition.
- **Fixed fights** (`World::ensureStoryEncounter`): one visible marker enemy (drawn gold)
  plus escorts that join the battle. `World::getActiveEncounterTag` tells `GameState` which
  fight was won. Fleeing puts the fight back and steps the party to a retreat tile.
- **Corporate Plaza is locked** until "The Data Chip" is complete
  (`World::setMapLocked`); the player is turned back with a message.
- **`StoryHud`** (`ui/StoryHud`): quest tracker, talk prompt, toasts, dialogue box with
  word wrap (`ui/TextWrap.h`), and an ending card. Rosé Pine colours.
- NPCs are solid; quest rewards pay full XP to every member and gold to the leader.
- `MAX_SPRITES` raised 1000 → 2000: text is one sprite per glyph.

**Bugs fixed along the way:**
- Map transitions fired mid-step, and the interrupted step kept interpolating on the new
  map. Walking north out of Central chained through Neon Alley's far exit and landed in
  Corporate Plaza. Transitions now wait for the step to finish and use
  `Player::teleport`, which cancels movement. **Use `teleport`, not `setPosition`, to
  relocate a player who may be mid-step.**
- `changeMap` spawned enemies before the biome was updated, so each district was populated
  from the previous district's encounter table.

14 CTest suites pass, including new `StoryTest`, which plays the whole chain headlessly.

**Not yet verified:** fixed-fight difficulty (thugs: 2 Street Thugs + Combat Cyborg at L2;
Enforcer L4 + 2 Security Drones L3) is a first guess — tune in phase 13.

### Phase 9a: Saving, Pause Menu, Result Screens — COMPLETE (2026-11-10)

Phase 9 was split when the audit for it found that no item or piece of equipment is ever
given to the player, so item and equipment menus would have had nothing to show. That
content, plus Settings, is phase 9b.

- **Save anywhere** from the pause menu. Saves live at
  `$XDG_DATA_HOME/CyberRayne/savegame.txt` (normally `~/.local/share/CyberRayne/`), not the
  working directory. Format `version=2` adds a `[WORLD]` section with the current map;
  version-1 saves still load and resume in Neo-Kyoto Central. Writes go to a `.tmp` file
  and are renamed into place, so a failed write cannot destroy the previous save.
- **Loading** builds the party and quest log in fresh objects and swaps them in only on
  success, reloads member textures, and uses `World::travelTo`, which snaps a mid-step
  position to a tile and falls back to the map's arrival point if the saved tile is not
  standable.
- **`PauseMenu`** (`ui/PauseMenu`): Resume, Party, Quests, Save Game, Quit to Title, drawn
  over the frozen world. Navigation is plain logic, compiled into `MenuTest` without
  Vulkan; drawing is behind `#ifndef NO_VULKAN`. Quit asks twice.
- **Victory card** (`State::BATTLE_RESULT`): XP, gold, level-ups. **Game-over card**: Enter
  loads the last save if there is one, otherwise returns to title.
- **Recovery, so HP loss cannot soft-lock a run:** members who are down at the end of a won
  battle get up with 1 HP, and the Street Vendor in Central restores the whole party for
  20 G (`StoryDirector::NODE_VENDOR_MEAL`).
- `ui/Theme` holds the shared Rosé Pine colours and panel drawing for all overlays.
- Dev shortcut: `CYBERRAYNE_START=load ./CyberRayne` resumes the saved game directly.
  Combine with `XDG_DATA_HOME=<dir>` to test against a scratch save.

15 CTest suites pass (new: `MenuTest`; `SaveLoadTest` and `StoryTest` extended).

### Phase 9b: Items, Equipment, Settings — COMPLETE (2026-11-10)

- **Shared party bag** (user decision: one bag, as in FF9). `Inventory` holds stacks keyed by
  catalog ID; `Party::getBag()` owns it. `Player`'s per-member inventory is gone.
- **`ItemCatalog`** (`Inventory.h`) creates every item from a stable string ID. **IDs are
  what saves store — renaming one orphans it in existing saves.** Seven items: Stim Pack,
  Trauma Kit, Defib Patch (revive), Shock Baton, Mono-Katana, Street Jacket, Kevlar Weave.
- `Item::canUseOn` is checked before anything is consumed, in battle and out. Healing items
  cannot raise the fallen; `ReviveItem` only works on them.
- **Battle items** come from the bag, are consumed on use (they never were before), and
  ask for an ally target. `ActionRequest::itemIndex` indexes the bag's *consumable* stacks;
  for items `targetIndex` indexes every party member, living or not.
- **Equipment** moves through `Party::equipFromBag` / `unequipToBag`, which swap with the bag
  so nothing is created or destroyed.
- New game starts with 3 Stim Packs, a Defib Patch, a Shock Baton and a Street Jacket
  (`ContentFactory::grantStartingKit`). "The Data Chip" rewards a Mono-Katana and 2 Stim
  Packs; "Corporate Intrusion" a Kevlar Weave and a Trauma Kit.
- **Saves** now include a `[BAG]` section and each member's weapon/armor ID. Unknown IDs are
  skipped rather than failing the load. A save with no `[BAG]` section predates the bag and
  is given the starting kit on load.
- **Pause menu** gained Items (use on a member) and Equipment (member → slot → piece) screens.
- **Settings** (`ui/SettingsMenu`), reachable from the title and the pause menu: rebind any of
  the eight actions, or reset. Bindings persist to `~/.config/CyberRayne/input.cfg`; a file
  that fails to parse or leaves an action unbound is ignored in favour of the defaults.
- **Input now goes through `InputConfig`.** `Game.cpp` used a hardcoded key table and ignored
  it. While `GameState::wantsRawKey()` is true the next raw key press goes to the rebind
  instead of being translated to an action. Esc always cancels a rebind.

### Combat balance (first pass, 2026-11-10; pulled forward from phase 13)

A play session ended in a wipe seconds after entering Neon Alley, so the fights were
measured instead of guessed. Simulating each fight 200 times per class showed:

- A Neon Alley ambush (Drone L3 + Thug L2 + Cyborg L3) beat a level 1 party 100% of the time.
- The Enforcer story fight was unwinnable for every class at levels 3 and 4.
- As a Netrunner, Rayne won the thug story fight 3% of the time at level 1.

Causes: enemies were two to three times faster than most of the party, so they took nearly
twice as many turns, and enemy defense outgrew party damage. **Combat snowballs** — results
jump from 0% to 100% across small stat changes — so tune by measurement.

Changes: speed, defense and bulk lowered for the five cyberpunk enemy types
(`EnemyTypes.cpp`); ambushes are 1-2 enemies, not 1-3; Corporate Plaza table capped at
level 3-4; thug fight is 2 Street Thugs L2 + Combat Cyborg L3; Enforcer fight is Enforcer L3
+ 2 Security Drones L3; "The Data Chip" pays 350 XP (was 200) so the party is level 3
before the plaza.

**`BalanceTest`** now simulates both story fights and every possible ambush pair in each
district, for all three classes, and fails below a 90% win rate. Its simulated player uses
damage abilities and focus-fires but never heals or uses items, so real odds are better.
Run `out/build/linux-debug/BalanceTest` to print the win-rate table.

**Open for phase 13:** everything currently measures 98-100%, which is probably too easy.
The test only sets a floor; there is no ceiling yet, and no measure of how much HP a fight
costs. Legacy fantasy enemy types were not retuned (unused by any encounter table).

17 CTest suites pass.

### Phase 10: Battle Presentation — COMPLETE (2026-11-10)

Battles are now a scene instead of bars on a blank screen.

- **`BattleSystem` reports what happened** through `takeEvents()`: ACTION, DAMAGE, HEAL,
  DEFEATED, MESSAGE. HP changes are found by comparing health before and after each step,
  so every source (attacks, abilities, items, poison, regen) is reported without each
  having to remember to. The logic still resolves instantly; the screen plays it back.
- **`ui/BattleFx`** (Vulkan-free, tested) turns events into floating numbers, a hit flash
  and shake, the attacker's lunge, defeated enemies fading out, and an action banner.
  `GameState` waits for `isBusy()` to clear before leaving the battle, so the last hit is seen.
- **`ui/BattleScene`** draws a per-district skyline backdrop (generated from rectangles, no
  image files), enemies on the left and party on the right in diagonal lines, enemy name
  and HP bars, status tags, and turn / target markers. It keeps every enemy's place on
  screen for the whole fight; `BattleSystem::getEnemies()` shrinks as enemies die.
- **`UIManager`** is now a Rosé Pine command panel plus a party panel with HP, MP and turn
  gauges. The `UIButton`-based battle menu is gone. The known gap from 9b is fixed:
  single-ally abilities list allies (`getLivingAllies()` order), not enemies.
- **`ui/SpriteLibrary`** loads art by name on first use:
  `assets/<category>/<spriteSlug(display name)>.png`. A new enemy or NPC needs a file, not
  code. Missing files draw a coloured block. `Sprite` already carries a `cols`/`rows` grid
  for animation sheets.
- **The map draws sprites too.** `World::render(renderer, sprites)` draws NPCs, enemies and
  the party leader together, sorted by row so whoever stands lower overlaps those behind.
  Story fights keep a gold plate under the feet.

**Bugs fixed along the way:**
- **Every UI colour was washed out.** The swapchain is an sRGB format, but tint colours were
  passed through as if linear, so `Theme::BASE` (#191724) displayed as a mid grey-purple.
  `VulkanRenderer::renderSprite*` now converts tints with `srgbToLinear`. **Pass colours to
  the renderer as they should look on screen.** Translucent layers blend in linear light,
  so a bright colour under a translucent dark one shows through more than the alpha
  suggests (`Theme::drawPanel` draws its border as strips for this reason).
- A member revived mid-battle never got another turn (fallen members are dropped from the
  turn order and were never put back).

Dev shortcut: `CYBERRAYNE_START=battle` starts a new game inside a mixed fight.

18 CTest suites pass (new: `BattlePresentationTest`).

**Not verified by hand:** a full fight played with the keyboard on the new screen (item and
ally-ability targeting, the result card over the battlefield). Hit flash tints red; a white
flash needs a shader change because tint multiplies the image.

### Phase 11 notes: Slice Art

Done (2026-11-10):
- The user generated all 17 base sprites (Rayne x3, Cyph, Vash, 5 enemies, 7 NPCs) into
  `CyberRayne/Raw/`, with prompts beside them. **`Raw/` is the user's working folder; do
  not modify it.**
- **Sprite spec changed to 96x128, original colours.** At the old 48x64 with the 16-colour
  palette the art lost faces, hair colour and skin tone. Characters, enemies and NPCs are
  conformed with `spriteprep.py --no-palette`; enemies may be 96x96 to 192x192 (Security
  Drone 112x104, Corporate Enforcer 144x192). `tools/asset_spec.py` and `ASSET_SPEC.md`
  are updated.
- All 17 are conformed into `assets/` and drawn in battle, on the map and on character
  select. Cyph and Vash have their own files.

- **Animation sheets are in (2026-11-10).** The user generated 22 sheets into
  `Raw/sheets/` (see its README). `tools/sheetprep.py` turns a raw sheet into an exact
  grid: it finds each pose by its outline (generated sheets are not on a true grid, and
  battle sheets are 1254 px wide, which does not divide by four), scales the sheet by one
  factor so the figure matches its standing sprite, and lines frames up on the feet.
  Rules are `SHEET_KINDS` in `tools/asset_spec.py`; the validator checks sheets.
  - `<name>_walk.png` (4x4: down, left, right, up): `Player` now has `getFacing()` and
    `getWalkFrame()`; `World::render` picks the frame. Turning works even into a wall.
  - `<name>_battle.png` (4x4: idle, attack, ability, guard): `BattleFx::getAction()` says
    which animation is playing; `BattleScene` draws it. Frames are wider than the standing
    sprite, so the standing sprite still sets size and label positions and the sheet frame
    is pinned by its bottom centre. **Keep the standing sprite; sheets are found through it.**
  - `<npc>_idle_talk.png` (4x2): idle loop on the map, talk row during their conversation.
  - Sheets are optional (`SpriteLibrary::sheet` / `memberSheet`); without one the standing
    sprite is drawn.
  - Not checked by hand yet: how the walk cycle and battle animations feel in motion
    (frame timing, any jitter between generated frames). Enemy map sprites do not animate.

**Bug fixed (2026-11-10): the game shut down when a fight started in Neon Alley.** Log:
`Exception caught: failed to allocate texture descriptor sets!` on the 76th texture. Every
descriptor set holds a uniform buffer and a sampler, but the pool reserved only two
uniform buffers; the driver tolerated that up to about 75 textures, and the animation
sheets pushed the count past it. The pool is now sized from
`VulkanRenderer::MAX_TEXTURES` (512), and loading past the limit returns -1 (placeholder)
instead of throwing. About 65 textures are loaded before any sprite sheet, most of them
tiles generated per map.

**Hold-to-walk and controllers (user request, 2026-11-10).** The game is meant to be
played on a controller (the user has a DualSense; Xbox and Steam pads must work too).
- `InputState` (`systems/InputState`, Vulkan-free, tested in `Phase5Test`) takes "which
  actions are held" each frame and produces press events, repeats for held directions
  (menus scroll), and the held direction (newest pressed wins). Keyboard and controller
  both feed it from `Game.cpp`.
- While exploring, `GameState` starts the next step in the same frame the last one ended,
  and `Player` carries leftover movement into it, so held walking is an even 8 tiles/s
  with no pause per tile. Walking into an NPC turns to face them.
- Controllers are read with GLFW's gamepad API (`pollGamepads` in `Game.cpp`): stick or
  D-pad moves, A/Cross confirms, B/Circle cancels, Start/Options or Y/Triangle opens the
  pause menu. **Linux only**: the Windows build does not use GLFW and would need XInput.
- Not done: controller buttons cannot be rebound; on-screen hints still say "Enter" and
  "Esc"; movement is still tile by tile (no free analog movement); no rumble.

**Window follows its real size (2026-11-10).** The user runs Niri, which tiles the window
to its own size (for example 1130x1378). The swap chain was always 1920x1080 and got
squashed to fit, so tiles were tall and narrow and walking up or down looked much faster
than sideways. `chooseSwapExtent` now asks GLFW for the real size, `drawFrame` rebuilds
the swap chain when the size changes (`recreateSwapChain`; Wayland never reports
out-of-date, so sizes are compared each frame), the window is resizable, and the title
menu lays its buttons out again on a size change. Every other screen already laid out
from the swap chain size each frame. Not checked: very small windows, and the Windows
build (unchanged).

**Smooth camera and walk speed (user feedback, 2026-11-10).** The view used to start on a
whole tile, so it stood still for half a step and then jumped a full tile. `Map::Viewport`
now has a fractional `startX`/`startY`/`widthTiles`: the camera centres on the player's
exact position and glides, tiles are exactly square at any window shape, and a map
narrower than the window is centred. `Player::WALK_SPEED` is 6 tiles/s (was 8, which the
user found a bit fast).

**Enemies now choose targets at random** (`BattleSystem::pickEnemyTargetIndex`). They
always hit the first living member, which was always Rayne. `BalanceTest` still reads
